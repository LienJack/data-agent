# 暂停积分与计费前端功能

## Goal

在主分析流程跑通前，暂停积分与模型计费相关的用户可见功能，避免用户进入尚不需要处理的账务控制面；保留既有服务端实现、数据库记录和模型选择能力，以便后续低成本恢复。

## Background

- 当前平台设置页会渲染积分账户、积分流水、模型账单、计费模式、价格与汇率审批面板。
- 工作空间路由 `/w/[workspaceId]/platform-settings` 直接复用同一个平台设置页；用户提供的 `/w/9e0ed5ae-7ab6-4896-b7eb-868e202f3725/platform-settings` 是该入口的一个实例。
- 超级管理员运维概览还会展示计费模式、计费健康门和价格审批快捷入口。
- `/admin/pricing` 是可直接访问的独立价格控制面。
- 模型列表与问答模型选择仍依赖现有模型配置读取链路；暂停计费 UI 不能阻断主流程选择和调用模型。

## Requirements

- R1：在 `/w/[workspaceId]/platform-settings` 等平台设置入口中，积分、模型计费、价格和汇率控制面默认不在前端渲染。
- R2：运维概览继续保留用户与工作空间管理，但不展示计费模式、计费健康门、余额/账单文案或价格审批入口。
- R3：直接访问独立价格控制面时返回未找到，不提供绕过隐藏入口的 UI。
- R4：使用一个服务端临时功能开关集中控制上述行为；默认关闭，后续可显式恢复，不能在多个组件中复制开关判断。
- R5：不删除或修改积分/计费 API、数据库迁移、账务状态、Worker 模型调用链、模型目录读取和已有账务数据。
- R6：不隐藏与主流程仍相关的模型选择、用户管理、工作空间管理和语义可移植性功能。

## Acceptance Criteria

- [x] AC1：默认配置下，任意 `/w/[workspaceId]/platform-settings` 页面（包括用户提供的工作空间 URL）都不挂载 `CreditLedgerPanel`、`ModelBillingPanel` 或 `PricingControlPanel`。
- [x] AC2：默认配置下，运维概览只显示身份相关健康信息，不显示计费 mode/epoch、价格/汇率/账单/余额健康门或价格审批快捷入口。
- [x] AC3：默认配置下，超级管理员直接访问 `/admin/pricing` 也得到 404；未登录访问仍遵循登录边界。
- [x] AC4：显式启用临时开关后，既有三个面板、运维计费信息和独立价格控制面可恢复，避免删除实现。
- [x] AC5：模型列表接口、问答模型选择和服务端积分/计费 API 不在本任务变更范围内。
- [x] AC6：新增针对默认隐藏与显式恢复的单元测试，Web 定向测试、类型检查和格式检查通过。

## Out of Scope

- 将数据库计费模式从 `ENFORCED` 切换到其他状态。
- 删除或回滚账务表、迁移、仓储、API、审计记录或历史余额。
- 重写模型配置、Provider/Billing 执行绑定或问答主流程。
- 重新设计平台设置页的其他功能。

## Technical Notes

- 功能开关只在服务端读取，避免暴露为可由浏览器伪造的权限或账务边界。
- 前端隐藏是当前产品范围控制，不构成服务端授权或账务状态变更。
- `apps/web/src/components/settings/operations-admin-panel.tsx` 已包含其他并行改动；实现和提交时只认领本任务对应的独立 hunks。

## Notes
