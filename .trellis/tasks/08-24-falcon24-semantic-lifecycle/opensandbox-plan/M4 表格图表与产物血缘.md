# M4 表格图表与产物血缘

## 目标

让分析结果稳定返回业务结论、机器可校验表格和对应图表，并能从任何输出追溯到 Cell、算子、输入数据、语义上下文与分析程序。

## 实现步骤

1. 定义 `DeclaredOutput`：name、kind、media type、path、schema、max bytes、producer、semantic role。
2. 输入与中间表统一使用 Parquet；小型解释/manifest 使用 JSON；图表只接受 PNG/SVG。
3. Cell 完成后宿主下载已声明文件，校验路径、大小、magic/MIME、SVG 安全、hash 和 schema。
4. 把图表与其 backing table、维度、指标、筛选、时间窗和展示格式绑定；持久化 artifact/receipt。
5. 报告渲染器同时展示表格和图表；若图表失败，分析节点不能假装完整成功。

## 代码分析

### 结构与职责

- Python 负责绘图，宿主负责声明、校验、存储与公开投影。
- 图表不是 stdout 截图；必须是具名文件产物。
- Oracle 校验机器表与图表 backing data，展示层不反向成为数值权威。

### 关键实现

PNG 校验签名、尺寸、字节上限；SVG 解析 root、拒绝脚本/外部引用/事件属性。输出路径规范化后必须位于专属目录，拒绝 `..`、symlink 逃逸和未声明文件。每个 chart manifest 记录 x/y/series、unit、sort、source table hash 和 producer cell。

Falcon24 五题最少图表：经营趋势与收入下滑分解、配送时效与评分场景、销量/损坏趋势象限或序列、渠道投入/转化/后续增长、cohort retention heatmap/曲线。

### 风险与坑点

- Base64 会放大内存和 JSON；文件 API 必须直接传字节。
- SVG 可承载脚本/外部 URL；未经净化不能公开。
- 图表使用聚合后数据而表格使用原始数据会造成口径分叉；必须绑定同一 backing artifact。
- 图表可四舍五入标签，机器表和 Oracle 输入不可四舍五入。

## 验收标准

- 每道 Falcon24 题至少有一个表格和一个图表，且 chart backing hash 可追溯。
- 非声明文件、超限文件、伪装 MIME、恶意 SVG、路径逃逸全部被拒绝。
- Artifact API/UI 能同时返回表格摘要和图表引用，不公开本地路径或 sandbox endpoint。
- 删除 sandbox 后，已提交 artifact 仍可独立读取和校验。

## 备注

只有在产物事务提交成功后，分析节点才可标记成功；否则进入可恢复的 artifact failure，而不是丢图返回半成品答案。
