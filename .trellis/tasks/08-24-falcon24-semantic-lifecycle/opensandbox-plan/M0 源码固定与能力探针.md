# M0 源码固定与能力探针

## 目标

用固定提交、固定 SDK/镜像版本和可重复探针验证 OpenSandbox 是否真的支持 Data Agent 所需的状态会话、文件传输、上下文隔离、图表下载、中断、删除与重建；同时明确不能从 M0 推导出的生产安全结论。

## 实现步骤

1. 固定 OpenSandbox 提交 `180554b146dceec254a5b98318c4c6fad056ff6b`，核对 npm 与服务器已发布版本。
2. 从官方 Code Interpreter 镜像构建临时 M0 镜像，固定 numpy/pandas/scipy/statsmodels/pyarrow/matplotlib/seaborn 版本，运行期禁装依赖。
3. 启动本地 `opensandbox-server==0.2.2`，默认拒绝网络，创建 agent/operator 两个 Python context。
4. 上传 Parquet，运行跨 Cell 变量复用，生成并下载 PNG/SVG，校验 magic/root 和 SHA-256。
5. 验证中断、删除 context、按 checkpoint 回放、删除 sandbox 和残留资源清理。
6. 分别用 PID 上限 32/128 测试科学计算库导入，记录实际资源下限。

## 代码分析

### 结构与职责

- `sdks/code-interpreter/javascript/src/services/codes.ts` 定义 create/list/get/delete context、run、interrupt。
- `sdks/code-interpreter/javascript/src/adapters/codesAdapter.ts` 把 Cell 请求映射到 execd API，并支持 `AbortSignal`。
- `docs/api/index.md` 定义 multipart upload、range download；适合替代 Base64 大信封。
- `server/opensandbox_server/services/validators.py` 验证 `networkPolicy` 与 runtime 组合，不能绕过平台约束。

### 关键实现

M0 已实际通过：sandbox 启动约 2496ms；agent/operator context 的 Python 状态相互独立；Parquet 上传读取成功；sealed 中间结果 SHA-256 为 `882ec631…`；PNG 16895 bytes、SVG 21824 bytes 且格式有效；interrupt 约 52ms；删除 context 后按 checkpoint 成功回放；sandbox 删除后无容器/volume 残留。context 共享同一容器文件系统，因此该探针不证明 Agent 与算子代码隔离；正式实现改用两个独立 sandbox。

临时镜像基于官方 `v1.1.0`，固定：numpy 2.2.6、pandas 2.2.3、scipy 1.15.3、statsmodels 0.14.5、pyarrow 23.0.1、matplotlib 3.10.3、seaborn 0.13.2。

### 风险与坑点

- SDK 文件 mode 使用十进制语义的 `755/400`，传 JavaScript `0o755` 会序列化为 493，造成权限偏差。
- PID=32 时 matplotlib/seaborn 导入出现 `can't start new thread`；PID=128 通过。旧运行时的 16 PID 限额不能机械平移。
- 本机只有 runc，M0 不能证明恶意代码强隔离。
- 官方校验明确阻止 gVisor 与 egress sidecar `networkPolicy` 的不兼容组合；生产需 Kata，或由 Cilium/CNI 承担域名出口策略。
- 基础 API 的只读 volume 不等于完整只读 rootfs。

## 验收标准

- 探针一次完成 context 状态、隔离、Parquet、PNG、SVG、中断、删除、回放和资源清理。
- 记录并固定所有 SDK、服务端、镜像与 Python 包版本/digest。
- PID=32 的失败和 PID=128 的成功都进入资源设计依据。
- 文档不把 Docker M0 描述为生产强隔离证明。

## 备注

M0 只产生研究证据和后续实现约束，不引入生产兼容路径。临时 API key、镜像 tag 和 `/tmp` 脚本不提交仓库。
