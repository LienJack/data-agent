# M5 安全资源错误与可观测性

## 目标

把“Python 运行失败”拆成可定位、可恢复、可量化的失败类型，并建立生产隔离、资源预算、取消清理和公开安全投影。

## 实现步骤

1. 建立错误 taxonomy：configuration、sandbox startup、transport、context、cell syntax/runtime、resource、operator contract/runtime、artifact、oracle、cleanup。
2. 分离 sandbox startup timeout、单 Cell timeout、operator timeout、总分析 deadline；超时调用 interrupt，随后强制终止和清理。
3. 分离容器 PID/内存/CPU 上限与 Cell 逻辑预算；用科学库预热和 Falcon workload 标定。
4. 生产部署增加 non-root、capability drop、seccomp、只读挂载、临时可写目录、网络默认拒绝和秘密隔离。
5. 记录安全可公开事件和内部诊断，聚合启动延迟、Cell 时长、重放率、资源峰值、错误分布和 cleanup debt。

## 代码分析

### 结构与职责

- OpenSandbox 提供生命周期与隔离载体；Data Agent 仍负责授权、错误语义、审计投影和恢复策略。
- runtime adapter 产生底层诊断；analysis executor 映射为稳定业务错误；public projector 只暴露安全字段。
- Oracle failure 与 Python runtime failure 必须区分，避免把模型内容错误误诊为平台超时。

### 关键实现

当前 Q1 失败已证明这一点：真实错误是 `FALCON24_Q1_KPI_IDENTITY_NOT_CLOSED`，原因是机器字段被 DeepSeek 舍入，而不是 Python 超时。Cell 结构应允许精度修复而不重跑 SQL/算子。

PID 标定必须保留 M0 证据：32 不足以导入绘图库，128 可行。生产强隔离门槛单独验证：Kata + OpenSandbox egress sidecar，或 gVisor + Cilium `toFQDN`；不得把不兼容组合静默降级为开放网络。

### 风险与坑点

- 超时后只 Abort 客户端而不 interrupt/kill，会留下执行和资源泄漏。
- stdout/stderr、异常栈和诊断日志可能含数据值、路径或 secret，公开 trace 必须限长和净化。
- 同一个 `PYTHON_EXECUTION_FAILED` 会妨碍自动恢复和容量规划。
- 本机 Docker 成功不能代替 Kubernetes runtime/securityContext 验收。

## 验收标准

- 每类错误有稳定 code、阶段、retryability、safe message、internal cause 和 recovery action。
- timeout/cancel 测试证明 Cell 中断、sandbox 销毁、无容器/volume/进程残留。
- 公开事件不含源码全文、原始行、token、endpoint、secret 或 provider payload。
- 生产部署未通过 Kata/Cilium 隔离门时 release gate 失败；不启用 fallback。
- 观测仪表可区分模型生成、运行时、算子、产物和 Oracle 失败占比。

## 备注

资源值是可校准配置，但其允许范围、镜像 digest 和安全组合是发布合同；不能由模型动态扩大。
