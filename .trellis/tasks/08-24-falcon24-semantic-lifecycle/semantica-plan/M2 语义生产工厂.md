# M2 语义生产工厂

## 目标

把 schema、血缘、Knowledge、人工编辑和模型建议统一生产为可评审、可发布、可回滚的语义 Release。

---

## 实现步骤

1. 将各来源归一化为 `SemanticAssertionCandidate`，区分物理事实、业务定义、模型推断和人工声明。
2. 按稳定 identity key 做实体解析与去重；冲突先形成分支候选，不自动覆盖。
3. 编译 SHACL-like 形状约束、Formula AST、粒度/Join、时间、权限、质量和循环依赖校验。
4. 把五个 Falcon 分析问题拆成可执行 Competency Cases，验证所需指标、关系和数据绑定可解析。
5. 冻结 ChangeSet，人审后在 PostgreSQL 单事务发布；随后异步重建图、稀疏和向量投影。
6. schema/lineage 漂移只创建 binding-impact Candidate，经验证与评审后进入新 Release。

---

## 代码分析

### 结构职责

- Semantica 的 `OntologyGenerator` 提供确定性 graph-to-ontology、`CompetencyQuestionsManager` 提供覆盖思路、`ProvenanceManager` 提供双向血缘和失效记录。
- Data Agent 继续复用现有 Candidate、Semantic Graph、Formula AST 和 Release 权威，不新增平行本体系统。

### 关键实现

- Competency Case 不是关键词命中，而是实际解析问题并检查 metric/formula/join/lineage/time/policy 闭包。
- Candidate 的来源证据和推断 premises 分离；模型候选不得改变 lifecycle state 为 published。

### 风险与坑点

- Semantica 的默认 GraphBuilder 会先持久化再查冲突，Data Agent 必须反序：校验通过后才能发布和投影。
- 自动实体合并会掩盖业务同名异义；低置信度或跨类型合并必须进入人工队列。

---

## 验收标准

- 冲突、循环、悬空关系、非法公式、错误粒度/Join 或越权绑定均阻止发布。
- 同一输入重放产生相同 Candidate/ChangeSet/Release hash。
- 每个发布对象可追溯来源、评审者、前一版本、有效时间及受影响绑定。
- 五个 Competency Cases 在 Falcon Release 上全部可执行，不以关键词相似度冒充通过。

---

## 备注

- LLM 本体生成仅用于 bootstrap Candidate；有结构化图后优先确定性生成和人工评审。
