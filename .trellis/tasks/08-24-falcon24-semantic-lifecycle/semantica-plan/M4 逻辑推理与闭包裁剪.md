# M4 逻辑推理与闭包裁剪

## 目标

在受控规则子集内完成可解释推理，并在 token 预算下保住能让模型正确分析的最小闭包。

---

## 实现步骤

1. 将已发布规则编译为分层 Datalog/前向链：等价词、传递血缘、指标依赖、Join 可达性、时间窗口和政策约束。
2. 推理采用 fixpoint、去重、最大轮次和最大派生数，禁止递归负例和不受控函数。
3. 每个结论生成 `InferenceReceipt`：premises、rule id、conclusion、release、valid time 和置信边界。
4. 构建 mandatory closure：选中指标必须带 Formula AST、grain、unit、source binding、join path、time、policy、quality 和 lineage。
5. 裁剪顺序为 mandatory closure → 直接证据 → 一跳解释 → 补充候选；用 token cost、MMR 和路径连通性压缩非必需内容。
6. mandatory closure 超预算时 fail/clarify，不返回看似完整但缺依赖的包。

---

## 代码分析

### 结构职责

- Semantica `Reasoner`/`DatalogReasoner` 提供前向、递归多跳和 premises 记录的参考。
- Data Agent 推理只消费 Published Release；模型推测作为 Hypothesis Candidate，不能混入事实闭包。

### 关键实现

- 规则 ID 和 release hash 决定推理身份；同一 facts/rules 顺序变化必须产生相同结论集合。
- 裁剪器操作语义簇和完整路径，不能按单条文本 score 截断。

### 风险与坑点

- 完整 OWL DL 难以保证终止和运行预算，不进入 Agent 在线路径。
- 传递规则可能在高连接图爆炸；需 predicate allowlist、深度和派生上限。

---

## 验收标准

- 规则重放字节稳定；循环、重复规则和输入乱序不会无限增长。
- 每个派生结论能还原完整 premises 路径，撤回 premise 后相关结论同步失效。
- token 压力测试不丢 Formula/Join/Lineage/Time/Policy/Quality 强制依赖。
- 不可闭合或超限时返回结构化 clarification/failure，不生成未经证明的答案。

---

## 备注

- UI 展示规则与证据链，不展示或重建模型内部思维链。
