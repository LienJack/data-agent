# M1 唯一合同与权威切换

## 目标

先冻结唯一运行合同和删除边界，避免后续继续扩散 V2/V3 与双解析路径。

---

## 实现步骤

1. 定义唯一 `SemanticContextPackage` 与 `AnalysisProgram`，运行时 schema registry 只接受各自一个版本。
2. 建立 PostgreSQL Published Semantic Release、Schema Snapshot、Permission Snapshot 的强绑定。
3. 列出并一次性迁移所有 Web、Worker、Semantic、Text2SQL、Platform、Evals 消费者。
4. 在隔离 worktree 完成原子切换；删除旧合同、resolver、planner、fixture、adapter 和导出。
5. 增加依赖边界测试，禁止重新引入旧符号或第二入口。

---

## 代码分析

### 结构职责

- Data Agent 现有权威基础位于 contracts、semantic context service 和 PostgreSQL artifact/release 路径。
- 当前探索分支的 `ResolvedContextPackageV3` 包装旧包，只能删除，不能成为最终设计。

### 关键实现

- 合同必须内容寻址并绑定 release/schema/permission/evidence hashes。
- 发布数据迁移是一次性迁移，不是运行时兼容读取；切换失败只能回滚整个提交/迁移。

### 风险与坑点

- 逐包迁移容易产生暂时双读；应在一个跨层切换提交中更新全部消费者。
- 只删导出不够，需扫描源码、生成物、测试和 migration fixture。

---

## 验收标准

- `rg` 与架构测试确认 V2/V3、旧 AnalysisPlan、旧 resolver 和 compat adapter 生产引用为 0。
- 所有 package build/typecheck 与跨层合同测试通过。
- 任一索引不可用时不会绕过 PostgreSQL 权威或权限快照。

---

## 备注

- 不保留 feature flag 双轨；可恢复方式是 Git revert 和数据库迁移回滚。
