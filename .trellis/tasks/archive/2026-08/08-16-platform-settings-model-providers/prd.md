# 平台设置模型供应商管理

## Goal

把 `/w/:workspaceId/platform-settings` 收敛为清晰的平台控制面：超级管理员通过“模型配置、组织与运维、语义管理”三个一级 Tab 管理系统能力，其中模型配置以供应商 Card 为主对象，能够新增供应商、读取该供应商可用模型，并选择模型是否启用。

用户价值是让“接入谁、接入了哪些模型、哪些模型可供运行”在一个页面内可见且可操作，而不是继续把供应商、模型目录、价格控制和组织运维混在一张长页面里。

## Background and Confirmed Facts

- 工作空间入口 `apps/web/src/app/w/[workspaceId]/platform-settings/page.tsx:1` 直接复用 `apps/web/src/app/settings/page.tsx`。
- 当前设置页按纵向区块渲染组织运维、可选计费控制和语义迁移，没有一级 Tabs，也没有挂载现有的模型供应商表单与列表。
- 现有未提交工作已经建立 OpenAI、Claude/Anthropic、DeepSeek、GLM、Kimi、Grok、Gemini、火山方舟、硅基流动和自定义 OpenAI-compatible 目录，以及供应商品牌图标、模型目录发现和模型配置表单。该工作属于用户现有改动，本任务复用并收口，不回退或覆盖。
- 当前权威模型控制面是 PostgreSQL `model_catalog`：只有 `SUPER_ADMIN` 可以通过 `/api/admin/models` 新增模型，并通过 `/api/admin/models/:id/status` 将模型置为 `ACTIVE`、`UNBILLABLE` 或 `DISABLED`。
- 环境系统模型是不可变投影；不能在管理页修改或删除。普通用户只能读取可用模型，不能配置供应商或更改模型状态。
- 公共 `/api/models` 的写入、删除和临时明文密钥发现接口已返回 410；任何新设计不能恢复进程内 Map 或把 API Key 回显到客户端。
- 仓库已有计费 UI feature flag。默认关闭时模型主流程仍必须可读可选，但价格、积分和结算 UI 不应被重新暴露。
- 本地 `.env` 当前只配置了 DeepSeek 与 Kimi 的凭据变量名称；本任务只读取安全投影，不修改、删除或回写任何 `.env` 文件或变量值。
- DataFoundry 固定提交 `f96477a81c080e60c1de2185abfdaa964a1d82b3` 将模型连接配置、连通状态和运行选择分开，并在影响连接的字段变化后把状态重新置为未测试。本项目借鉴该状态语义，但采用“一个供应商连接包含多个可发现模型”的产品模型。

## Requirements

### R1. 一级信息架构

- 页面提供三个一级 Tab，顺序固定为“模型配置”“组织与运维”“语义管理”。
- “模型配置”是默认 Tab。
- URL、刷新和工作空间壳层保持兼容；Tabs 在窄屏可访问且不产生横向溢出。

### R2. 权限与可见性

- 超级管理员可以查看并操作模型供应商、模型状态和现有组织运维能力。
- 非超级管理员可以查看模型配置的安全投影，但不得看到新增、密钥、启停等写操作。
- 环境系统模型显示“系统托管/不可修改”状态，禁止复用普通模型的写操作。
- 任意由环境变量投影出的供应商连接及其系统模型均不可编辑、停用、归档或删除；当前至少覆盖 DeepSeek、Kimi，并为未来配置 `ZAI_API_KEY` 后的 GLM 保留同一规则。

### R3. 供应商 Card 布局

- 模型配置以供应商 Card 为核心，而不是把每个模型都提升为独立大 Card。
- 首批内置供应商至少覆盖 OpenAI、Claude、DeepSeek、Kimi、智谱 GLM；继续兼容现有 Grok、Gemini、火山方舟、硅基流动和自定义 OpenAI-compatible 平台。
- 排序优先级固定为 DeepSeek、Kimi、智谱 GLM，其后才是 OpenAI、Claude 与其他供应商。
- Card 显示品牌标识、接入方式、连接/配置状态、已启用模型数和模型总数，并提供进入配置的明确动作。
- 原生供应商与第三方聚合平台在视觉和文案上可区分，但使用同一 Card 组件和状态模型。

### R4. 新增与配置供应商

- 超级管理员可从供应商目录新增一条供应商配置；第三方聚合平台至少支持 OpenAI-compatible Base URL。
- 配置过程必须复用服务端权威模型命令和 SecretRef 安全边界，不得持久化或回显客户端明文密钥。
- 所有供应商统一按 API Provider 实现，不接入 Claude Code CLI、OAuth 会话或本机订阅运行时。
- 同一供应商连接包含一组共享 Base URL/凭据的模型；管理员新增的连接可以修改，并可通过审计保留的归档删除从可用列表移除。
- 保存失败、权限不足、版本冲突和连接失败需要提供内联错误状态。

### R5. 获取模型与启停

- 已配置供应商可触发“获取模型”，从该供应商读取当前账号可用的多个模型；目录加载、空结果、失败、过期需要独立状态。
- 获取成功后，管理员在同一供应商 Card/配置面板内逐个选择是否启动模型；选择启动对应权威状态 `ACTIVE`，取消选择对应 `DISABLED`。
- 尚未完成凭据、连通性或价格门禁的模型保持显式非活动状态，不得伪装为可运行；界面要说明阻断原因。
- 模型状态切换必须使用 `expected_config_version`，避免并发覆盖。
- UI 操作完成后重新读取权威模型目录，而不是只做本地乐观假象。

### R6. 现有控制面迁移

- “组织与运维”承载现有 `OperationsAdminPanel`；计费 UI 显式开启时，相关积分/价格控制仍受原 feature flag 与超级管理员权限约束。
- “语义管理”承载现有 `SemanticPortabilityPanel`，不改变 PostgreSQL 语义权威与导入治理合同。
- 不删除现有页面能力；只调整信息架构、组合方式和模型配置体验。

### R7. UI 完整状态

- 为 Tabs、供应商 Card、模型目录和写操作覆盖加载、空状态、错误、成功反馈和禁用态。
- 使用项目现有 CSS tokens、Button/Card/Badge 等组件和 Phosphor 图标，不引入新 UI 依赖，不使用 emoji。
- Card 在桌面采用有层次的非等分布局，在移动端回落为单列；交互包含清晰 hover、focus-visible 和 active 反馈。

## Acceptance Criteria

- [ ] AC1：访问任意 `/w/:workspaceId/platform-settings`，页面首屏显示三个一级 Tab，默认选中“模型配置”。
- [ ] AC2：超级管理员在模型配置 Tab 能看到按供应商聚合的 Card，至少包含 OpenAI、Claude、DeepSeek、Kimi、智谱 GLM 与第三方聚合平台入口。
- [ ] AC3：管理员可新增一个 API 供应商连接、一次读取该供应商的多个模型、逐个选择是否启动并保存；凭据不出现在列表响应、错误消息、HTML 或浏览器日志中。
- [ ] AC4：管理员可把非系统模型在 `ACTIVE` 与 `DISABLED` 间切换；请求携带当前配置版本，成功后刷新 PostgreSQL 权威投影。
- [ ] AC5：当前 `.env` 投影的 DeepSeek/Kimi 连接和模型显示为不可变且没有编辑/删除操作；以后由环境变量投影的 GLM 遵循相同规则；普通用户不能通过 UI 或 API 完成供应商新增和模型启停。
- [ ] AC6：“组织与运维”和“语义管理”分别承载现有功能；默认关闭的计费 UI 不会因改版重新出现。
- [ ] AC7：供应商/模型加载、无配置、目录为空、发现失败、保存失败和版本冲突均有可理解的页面内状态。
- [ ] AC8：相关 Vitest、Web typecheck 和范围内 Biome 检查通过；登录后的目标页面在桌面与窄屏完成浏览器验证。
- [ ] AC9：本任务只提交任务规划和明确拥有的页面/模型配置文件，不吸收工作区其它并行改动。

## Out of Scope

- 本任务不宣称完成 Q&A `createRun`/Worker 的真实模型切换绑定；该链路由独立任务负责。
- 不修改模型价格、积分结算和供应商账单算法。
- 不把 Neo4j 或任何前端缓存提升为语义或模型配置权威。
- 不自动抓取供应商价格，不让 AI 自动批准、启用或发布模型。
- 不实现任意供应商插件市场；首期自定义接入以明确的 OpenAI-compatible 合同为边界。
- 不物理删除模型配置版本、审计记录或历史运行引用；用户动作“删除供应商”采用归档语义。
