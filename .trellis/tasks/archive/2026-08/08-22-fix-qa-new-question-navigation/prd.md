# 修复新建业务问题未创建对话

## Goal

让用户点击侧边栏“新建业务问题”后，立即创建并激活一条空白业务问题对话，并进入带有新对话 ID 的可刷新 URL。

## Requirements

- 侧边栏入口必须调用现有 Q&A store 的 `createConversation`，不能仅导航到当前 `/qa` 路由。
- 创建成功后，使用统一的 `qaConversationHref` URL 构造器跳转到 `?conversation=<new-id>`。
- 创建过程中阻止重复提交，避免一次连续点击生成多条空白对话。
- 创建失败时保持当前页面，不跳转到不存在的对话；沿用 store 现有错误状态供界面展示。
- 沿用 `createConversation` 已有的资源默认值选择、激活新对话、清空消息与事件等行为，不另建第二套状态逻辑。

## Acceptance Criteria

- [x] 点击“新建业务问题”只发起一次创建请求。
- [x] 创建成功后，新对话成为当前活动对话，聊天区为空白状态。
- [x] 浏览器地址包含新对话 ID，刷新后仍可恢复该对话。
- [x] 创建未完成期间再次点击不会创建重复对话。
- [x] 创建失败时不改变当前路由，并保留可见错误状态。
- [x] 新增回归测试在修复前失败、修复后通过；Web 相关测试与类型检查通过。

## Notes

- 已确认根因：当前入口是指向同一路由的普通链接，没有执行创建动作；页面只在首次挂载时读取查询参数。
- 使用现有 `createConversation` 和 URL helper，避免扩大到对话目录重构或发送消息流程。
- 范围仅包含 Q&A 侧边栏入口及其回归测试，不包含数据库清理、页面视觉重构或无关生成文件。
