# M3：语义绑定影响候选

## 目标

把物理 schema drift 转换为可验证的语义绑定影响 Candidate/receipt，明确哪些 mapping、维度、指标、公式、join 和下游对象需要评审；禁止自动重绑或直接发布。

## 实现步骤

1. 新增 `packages/contracts/src/artifacts/semantic-binding-impact.ts`，定义 drift ref、snapshot/release ref、direct/transitive impact、风险、建议动作、不可自动判断原因和 Candidate ref。
2. 保留 `packages/contracts/src/catalog/schema-drift.ts` 的 drift event 作为物理事实；不扩展或改写历史 event，而是以唯一当前 Binding Impact artifact 表达派生结论。
3. 新增 `packages/semantic/src/induction/binding-impact-planner.ts`，把 relation/column/constraint/FK operation 映射到当前发布物理 binding。
4. 复用 `packages/semantic/src/induction/impact-planner.ts` 计算传递依赖闭包与 unchanged hashes。
5. 新增 `packages/platform/src/semantic/postgres-semantic-binding-impact.ts`，以及 `infra/supabase/apps/data-agent/migration-sources/10706/`、`scripts/render-10706-migration.ts` 和 `infra/supabase/apps/data-agent/migrations/20260725010706_app_data_agent_semantic_binding_impact.sql`；该 forward-only migration 承载 append-only receipt/RPC，暂定 `10706`，实施前确认 migration inventory。
6. 生成 Candidate 与 validation input，由现有事务/人工评审/发布链处理；不在 planner 中写发布表。
7. 对每类漂移操作先写失败测试，验证幂等、陈旧拒绝、权限和跨 datasource 隔离。

## 代码分析

TIS 的 Binding Switch Report 提供 missing/extra column 与阈值视角，但当前实现的 type mismatch 列表不完整，且简单阈值不能证明语义可安全切换。Data Agent 的 `schemaDriftOperationSchema` 已覆盖类型、可空性、默认值、PK/FK/约束/索引；`planSemanticImpact` 已有稳定依赖闭包，所以应组合现有能力，而不是复制报告算法。

建议动作只表达 `REVIEW_MAPPING`、`REMAP_COLUMN`、`REVALIDATE_FORMULA`、`REVALIDATE_JOIN`、`NO_SEMANTIC_ACTION`、`MANUAL_INVESTIGATION` 等受控类别。任何自动生成的 replacement id 都必须被当成 Candidate 内容，而不是事实。

## 验收标准

- 列删除、类型/可空性变化、FK/唯一约束变化可定位直接与传递影响；
- 注释变化和新增未绑定列不会被夸大成必然破坏；
- 多映射歧义、未知 lineage、陈旧 snapshot、release mismatch 显式标为人工调查或拒绝；
- 循环依赖闭包终止，排序与 hash 稳定；
- 同一 drift/release 重跑幂等；不同 release 不复用结果；
- append-only receipt 通过 PostgreSQL scope/capability 鉴权并可由 public ref 安全读取；
- planner 不执行发布写入、不调用 provider、不运行 SQL；
- artifact 可由安全 public ref 预览并追溯到 drift event。

## 备注

本阶段优先回答“谁受影响、为什么、需要什么评审”，不承诺自动生成正确的新物理映射。自动 patch 属于后续独立安全设计。
