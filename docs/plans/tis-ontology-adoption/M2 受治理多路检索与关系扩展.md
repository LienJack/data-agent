# M2：受治理多路检索与关系扩展

## 目标

在 M1 的确定性语义落点之后，按需加入知识候选和精确版本关系子图，补齐当前 deferred 路由；所有非确定性召回只提供候选证据，不能成为发布事实或绕过消歧。

## 实现步骤

0. 先评估 M1 固定回放/Falcon 数据；只有 unresolved 缺口仍显著且不能通过补充显式词汇解决，才启动本阶段。
1. 新增 `packages/semantic/src/context/governed-retrieval.ts`，统一候选类型、去重、排序、容量估算和 fallback。
2. 复用既有 knowledge port，不把 provider payload 或 raw chunk 直接写入 Resolved Context；结果必须映射回 Published Release 对象或受治理 knowledge ref。
3. 复用 `packages/semantic/src/relationship-index/service.ts` 做 bounded graph read，绑定 exact release/checkpoint/digest。
4. 修改 `packages/semantic/src/context/resolver.ts`，按 lexical → knowledge candidate → relationship expansion → capacity/policy 的顺序组装证据。
5. 必要时只在 `packages/contracts/src/ports/semantic/application.ts` 增加最小异步读取端口，不暴露 Neo4j 驱动或搜索实现。
6. 使用离线比较 artifact 对照批准基线；实现后原子替换当前运行路径，不保留旧 resolver 分流或兼容开关。

## 代码分析

TIS `DefaultGraphRAGService.java` 的实用启发是并行检索不同本体面并做关系展开；但其 embedded Neo4j、通用 `LINKED_TO`、向量任务与字典结果直接混合，以及粗略 token 估算不符合 Data Agent 边界。Data Agent 已有精确版本关系索引、context policy/capacity 和 knowledge refs，应把多路检索放在这些边界之内。

当前 `packages/semantic/src/context/resolver.ts` 在 GRAPH 路径上截取 `published_relationships.slice(0, 128)`，只是容量保护，不是相关子图选择。M2 应先由 M1 给出 seed object，再通过现有 relationship service 读有界邻域；找不到 seed 时不能遍历全图猜答案。

## 验收标准

- 有批准的 M1 后召回缺口基线与 U3 go/no-go 记录；未达门禁时本阶段保持暂缓；
- 非确定性候选不能单独把 REJECTED/NEEDS_CLARIFICATION 提升为 READY；
- 知识结果通过 workspace/ACL/egress policy，并以 versioned resource ref 表达；
- 图读取绑定 exact release/checkpoint/digest，不能读取 latest；
- hop/node/edge/context capacity 超限产生稳定 PARTIAL/REJECTED reason；
- Neo4j/知识索引禁用、陈旧、超时、digest mismatch 时回到 lexical-only；
- 重复命中、无关高分和跨 release 对象被确定性去除；
- 公共事件与 artifact 不包含 raw prompt、raw chunk、SQL、rows、DSN 或 provider payload。

## 备注

若现有 knowledge port 无法提供版本、权限或安全摘要，先停在 lexical + relationship read，不为追求 TIS 式“四路召回”新增不受治理的直连。
