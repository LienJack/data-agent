# M0：参考实现核验与采用门禁

## 目标

固定 TIS 参考版本、源码证据、采用矩阵和 Data Agent 当前能力基线，避免后续实施从 README 宣传或上游 latest 漂移出发。M0 只交付决策文档，不修改运行时代码。

## 实现步骤

1. 固定 `datavane/tis@21edc599e...` 与 `qlangtech/plugins@1ba03fe...`，记录许可证、commit、关键文件和静态检查边界。
2. 将上游能力拆为本体模型、词汇、关系、检索、同步、推理、绑定维护、SQL 执行和测试九类。
3. 逐项与 Data Agent 的 Published Semantic Release、Semantic Graph V2、Ontology Package、Resolved Context、relationship index、schema drift、Candidate、Falcon gate 比较。
4. 为每项给出“采用、改造采用、不采用、暂缓”结论，并写清权威与安全原因。
5. 以 `858446e` 作为当前语义重构基线；每个实施单元开始前检查受影响路径，有冲突则在独立 worktree 开始，不覆盖并行修改。

## 代码分析

### TIS 来源

- `tis-plugin/src/main/java/com/qlangtech/tis/plugin/ontology/Ontology*.java`：ObjectType、Property、Glossary、SharedProperty、ValueType、Linker 等领域抽象。
- `design/chat-bi/03-graphrag-retrieval.md`：字典、向量和图扩展设想。
- `tis-ontology-plugin/.../ontology/graphrag/DefaultGraphRAGService.java`：字典 + 四类向量任务、关键词回退和关系扩展。
- `tis-ontology-plugin/.../ontology/sync/OntologyNeo4jSyncService.java`：文件/XML 来源到 Neo4j 的全量/增量同步。
- `tis-ontology-plugin/.../ontology/chatbi/DefaultChatBIService.java`：召回、prompt、SQL 生成、校验和查询执行。
- binding switch / infer 源码：漂移报告和分阶段 LLM 推断；当前实现存在类型不匹配检查不完整、真实 DB 测试被忽略以及本地绝对路径调试输出等风险信号。

### Data Agent 对照

- `packages/contracts/src/artifacts/semantic-graph-v2.ts`：一等语义节点、typed edges、term roles、物理与 provenance 关系。
- `packages/contracts/src/artifacts/ontology-package.ts`：constraint、physical mapping、metric binding、Candidate 与 validation receipt。
- `packages/contracts/src/context/resolved-context-package.ts`：精确权威快照、policy、provider、容量和 evidence。
- `packages/semantic/src/relationship-index/service.ts`：精确 release/checkpoint/digest 与可解释回退。
- `packages/contracts/src/catalog/schema-drift.ts`：物理漂移表达完整，但 binding impact 尚未知。

## 验收标准

- 两个参考仓库的 commit、许可证和关键文件可复核；
- 采用矩阵覆盖上述九类能力，没有“整体照搬”的模糊项；
- PostgreSQL 权威、Neo4j 可重建投影、Formula AST、Candidate-only、QueryEvidence 等边界明确；
- 后续每个阶段都包含目标文件、测试场景、失败模式和回滚边界；
- current-only、无兼容层、无旧数据迁移的执行约束已覆盖主方案与 M1–M4；
- 本阶段没有运行时代码、依赖、schema 或配置变化。

上游测试只做静态阅读，不用 `assertNotNull` 或被 `@Ignore` 的测试反推生产可用性。上游更新不自动改变本方案；若要吸收新能力，先重新固定快照和修订采用矩阵。
